# Конвертер конфигураций Chiaki-ng

## Проблема

Chiaki-ng использует формат конфигурации на основе INI файлов с форматом `@ByteArray(...)` для хранения бинарных данных (ключей, MAC адресов и т.д.). 

Формат `@ByteArray` может содержать:
- Hex escape-последовательности: `\xHH`
- Null байты: `\0`
- Escape-последовательности: `\n`, `\t`, `\r`, `\a`, `\b`
- Обычные символы

**Проблема**: При попытке интегрировать конфиг из chiaki-ng в другие приложения возникают ошибки "RP mismatch", потому что:
1. Формат `@ByteArray` с escape-последовательностями неправильно парсится другими приложениями
2. `rp_regist_key` может быть сохранен как hex-строка (например, `6b18efc2\0\0...`) вместо бинарных данных
3. MAC адреса в формате `@ByteArray(,\x9e\0\xb3O\xa2)` могут быть неправильно интерпретированы

## Решение

Скрипт `convert_chiaki_config.py` конвертирует INI конфиг chiaki-ng в JSON формат с правильной base64-кодировкой всех бинарных данных.

### Размеры ключей

- `rp_key`: 16 байт (0x10)
- `rp_regist_key`: 16 байт (0x10, CHIAKI_SESSION_AUTH_SIZE)
- `server_mac`: 6 байт

### Использование

```bash
python convert_chiaki_config.py <input.ini> [output.json]
```

Пример:
```bash
python convert_chiaki_config.py plusaccount.ini output.json
```

Если `output.json` не указан, автоматически генерируется имя файла (например, `plusaccount.json`).

### Пример конвертации

**Входной INI файл** (`plusaccount.ini`):
```ini
[registered_hosts]
1\target=1000100
1\server_mac="@ByteArray(,\x9e\0\xb3O\xa2)"
1\rp_regist_key=@ByteArray(6b18efc2\0\0\0\0\0\0\0\0)
1\rp_key=@ByteArray(\x83\xb2\x10\xdf\x33\x97\xee\x1bY\n\xf7t\x98\x36\a6)
```

**Выходной JSON файл** (`output.json`):
```json
{
  "format": "chiaki-settings",
  "version": 2,
  "settings": {
    "registered_hosts": [
      {
        "target": "PS5_1",
        "server_mac": "2c:9e:00:b3:4f:a2",
        "rp_regist_key": "axjvwgAAAAAAAAAAAAAAAA==",
        "rp_key": "g7IQ3zOX7htZCvd0mDYHNg==",
        "rp_key_type": 2
      }
    ]
  }
}
```

## Как это работает

### Парсинг @ByteArray

Скрипт правильно парсит формат `@ByteArray`, обрабатывая:
- Hex escape-последовательности `\xHH`
- Null байты `\0`
- Специальные escape-последовательности (`\n`, `\t`, `\r`, `\a`, `\b`)
- Обычные символы

### Обработка hex-строк

Для `rp_regist_key` скрипт определяет, если значение является hex-строкой (например, `6b18efc2\0\0...`), и правильно конвертирует её в бинарные данные.

### Корректные размеры

Скрипт проверяет и дополняет ключи нулями до правильного размера:
- `rp_key`: дополняется до 16 байт
- `rp_regist_key`: дополняется до 16 байт

## Фильтрация активного хоста

При импорте конфига в chiaki-ng обычно предлагается подключиться только к одной консоли (активному хосту). Скрипт автоматически определяет и оставляет только активный хост.

**Логика определения активного хоста:**
1. Проверяется секция `[manual_hosts]` на наличие записей с `registered=true`
2. Если найдена такая запись, берется MAC адрес из `registered_mac` - это активный хост
3. Если не найдено, берется первый хост из `[registered_hosts]`

**Пример:**
```ini
[registered_hosts]
1\target=1000100
1\server_nickname=PS5-855
1\server_mac="@ByteArray(,\x9e\0\xb3O\xa2)"
...

[manual_hosts]
1\host=77.37.160.252
1\registered=true
1\registered_mac="@ByteArray(,\x9e\0\xb3O\xa2)"
```

В этом случае скрипт определит хост с MAC `2c:9e:00:b3:4f:a2` как активный и оставит только его в выходном JSON.

## Проверка результата

После конвертации проверьте:
1. Размеры ключей (должны быть 16 байт)
2. MAC адреса (должны быть в формате `XX:XX:XX:XX:XX:XX`)
3. Base64 кодировка (все ключи должны быть в base64)

Вы можете декодировать base64 для проверки:
```python
import base64
# Проверка rp_key
rp_key_b64 = "g7IQ3zOX7htZCvd0mDYHNg=="
rp_key_bytes = base64.b64decode(rp_key_b64)
print(f"RP Key (hex): {rp_key_bytes.hex()}")
print(f"RP Key size: {len(rp_key_bytes)} bytes")  # Должно быть 16
```

## Проблемы и решения

### Ошибка "RP mismatch"

Если после конвертации все еще возникает ошибка "RP mismatch":
1. Убедитесь, что размеры ключей правильные (16 байт)
2. Проверьте, что ключи не содержат неправильные данные
3. Убедитесь, что hex-строки правильно конвертируются в бинарные данные

### Проблемы с MAC адресом

Если MAC адрес не парсится:
- Проверьте формат в INI файле
- Убедитесь, что MAC адрес содержит 6 байт после парсинга

## Формат rp_regist_key для Android

**Важно**: Android приложение chiaki-ng ожидает, что `rp_regist_key` будет hex строкой, закодированной в UTF-8 байты (ASCII символы), а не как hex байты.

### Пример

Если `rp_regist_key` в INI файле: `@ByteArray(6b18efc2\0\0\0\0\0\0\0\0)`

**Правильный формат для Android**:
- Hex строка "6b18efc2" конвертируется в UTF-8 байты (ASCII): `36 62 31 38 65 66 63 32`
- Дополняется нулевыми байтами до 16 байт: `36 62 31 38 65 66 63 32 00 00 00 00 00 00 00 00`
- Кодируется в base64: `NmIxOGVmYzIAAAAAAAAAAA==`

**Неправильный формат** (вызовет ошибку):
- Hex строка "6b18efc2" конвертируется в hex байты: `6b 18 ef c2`
- Это приведет к ошибке `NumberFormatException` в Android приложении

Android приложение обрабатывает `rp_regist_key` так:
1. Декодирует base64 в байты
2. Находит первый нулевой байт
3. Берет часть до первого нуля
4. Конвертирует в UTF-8 строку (например, "6b18efc2")
5. Интерпретирует как hex число с помощью `toULong(16)`

Скрипт автоматически конвертирует hex строку в правильный формат.

## Технические детали

### Формат @ByteArray в QSettings

Qt QSettings использует формат `@ByteArray(...)` для хранения бинарных данных в INI файлах. Формат позволяет использовать escape-последовательности для специальных символов.

### Различия между форматами

- **INI формат** (`@ByteArray`): Использует escape-последовательности, может содержать hex-строки
- **JSON формат**: Использует base64 для кодирования бинарных данных

Скрипт корректно преобразует между этими форматами, правильно обрабатывая все edge cases.
